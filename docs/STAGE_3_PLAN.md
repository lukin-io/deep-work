## Reuse the existing foundation

- `AppModel` already owns report period/date and an optional schedule draft. Journal opens on launch, Week is selected, and tab changes preserve the timer. Extend this shared owner with typed selection, grouping, source, pagination and draft state; do not create another timer or storage owner.
- `SessionRecord`, `ActiveSegment`, `WorkSchedule`, `CivilDate` and `JournalDocument` already provide validated models. SQLite already stores actual records, configuration, schedule and checkpoint transactionally. `TimerEngine.liveRecord` provides a nonmutating current-focus observation. Reuse these contracts; a reporting-only change should not require a schema migration.
- `JournalView` contains the approved section structure, schedule summary, storage status and Focus shortcut. Reports, examples, schedule editing, date controls and metrics are still unavailable. J-001, J-002, J-052 and J-053 are partial; their scaffolding is not accepted reporting behavior.

## Arithmetic and state cases that must be covered

- Use **[From, Until)**. Clip each active segment; count a Complete record only by its finish timestamp. Include completion-only rows with zero in-range focus and focus-only rows whose completion is outside the range. Preserve raw timestamps, subsecond precision and original Started/Ended values; round only display/export formatting. Partial and live focus contribute time, never completed cycles; paused gaps and breaks contribute neither.
- Allocate across midnight and non-midnight cutoffs, including exactly 04:00 and exactly Until. Chart day/week sums and session-row sums must equal the metric's unrounded time; changing grouping must preserve row membership and totals. Days with focus divides by **every overlapping reporting date**, including empty/future dates. Scheduled days is separate context; off-day focus remains included.
- Port the ten reporting-reference scenarios into native tests, including Kyiv spring/fall DST, 23/25-hour days, week starts and shifts before their anchor. Use valid native session fixtures: some generic JavaScript tests permit durations/outcomes or zero rest days that the native domain intentionally rejects. Preserve their arithmetic assertions through valid records or calendar-unit cases; do not weaken model validation or reproduce JavaScript's silent sanitization of corrupt stored records.
- Calendar navigation adds civil days, not fixed 24-hour intervals. Cutoffs choose the earlier repeated time and move missing local times forward; explicit Range inputs reject missing local times and choose the earlier repeated occurrence. Exercise leap days, month/year boundaries, all seven week starts and positive modulo before/after a shift anchor.
- Test missing/invalid endpoints, equal/reversed endpoints, exactly and just beyond **3,660 × 24 elapsed hours**, and exactly/just above **93 × 24 elapsed hours**. Above 93 days forces weekly grouping; shortening does not switch back automatically. Today exits Range to Day but preserves its inputs; Day/Week navigation and schedule save do not rewrite custom range inputs.
- Test 0, 1, 12, 13 and 25 matching rows. Navigation, source changes, drilldown and schedule save reset pagination; grouping alone retains it. Refresh clamps the page when results shrink. A clipped chart bucket opens the **full** selected reporting day/week, retains actual/example mode and returns grouping to By day, including empty/off-day buckets.
- Validate schedule raw input, including blanks, fractions, 0/32, valid 1/31 endpoints, missing/invalid anchor and 00:00/23:59 cutoffs. Zero selected weekdays is valid and differs from Any day. Preserve inactive mode input and drafts across tab changes; invalid drafts clear the preview and disable Save. Preview 14 consecutive reporting dates using the draft cutoff.
- Generate the specified 35-date example dataset once per launch: weekday counts, alternating 60/90-minute plans, second-session pause, gaps and partial Tuesday/Saturday records; omit future-ended records. Initial example mode requires both empty actual history and no checkpoint. Starting real focus selects actual history. Source switches preserve report selection and never persist examples.
- Exercise slow/failed SQLite saves, concurrent timer boundaries during schedule save, hidden-window timing, paused recovery and rapid report/source changes. No stale save may overwrite a newer record/checkpoint; no report refresh may finalize twice or turn a paused observation into completed history.

## Native decisions to record before the affected implementation

No unresolved product decision blocks beginning the report engine. Record these choices in `NATIVE_DECISIONS.md` while implementing them and verify relevant Apple APIs:

1. **Time-zone changes:** preserve the reference's current-device-zone reporting, with no new zone picker. Recompute calendar bounds/labels when the device zone changes; keep original absolute session timestamps and monotonic timer accounting unchanged. Retained custom inputs remain civil date/time values interpreted in the current zone, matching the reference. Test a zone change while running and while paused; do not silently freeze a report to the launch zone.
2. **Schedule save failure:** the browser closes and announces success even when persistence fails. Native code must retain recoverable edits and expose failure; announce “saved” only after SQLite confirms success. Keep the draft available on failure. Document the exact pending/failure presentation and test it with real failing storage.
3. **Draft versus stored validation:** allow incomplete raw editing values without corrupting the already validated persisted model. Hidden invalid shift text must not make Any day unusable; retain raw edits for returning to that mode and retain valid typed inactive values when committing another mode. Keep existing corruption-preservation rules rather than copying browser fallback defaults.
4. **Reference details:** preserve documented Range titles without a year and the current weekly-highlight rule unless separately changed. Use native accessible bar buttons and table semantics without adding sorting, editing, selection actions, metrics or schedule automation. Visual capture capability alone is not accessibility/VoiceOver acceptance.
